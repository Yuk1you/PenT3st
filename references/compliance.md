# 合规与合法红线

在编写报告前,本文件必须被读取并逐条比对。任一项不通过 → finding 撤回 / 重新评估。

**本文件是「动作尺度」的唯一裁决点。** 「能提权到哪一级」「能不能碰核心资产」「拿到凭据能用到什么程度」这类问题一律以本文件为准；`references/playbooks/*/00-index.md` 只描述攻击手法与利用链，**不自行定义许可边界**。各 playbook 里的「不要做的事」小节是类型特定红线，与本文件冲突时取更严格的一项。

---

## 前提：授权是一切的基础

渗透测试的所有操作必须在 Phase 1 确认的**书面授权范围**内进行。授权文件（合同/授权书/邮件确认）是法律保护的唯一依据。没有授权 = 违法，无例外。

---

## ❌ 绝对禁止

- **出 scope 资产**:目标不在 Phase 1 已确认的授权范围 → 立即停手,向项目负责人上报。
- **破坏业务数据**:禁止删除、篡改生产环境中的真实业务数据。写操作仅在**自己控制的测试对象**上验证。
- **服务中断**:禁止导致生产系统不可用的操作（大流量扫描/fork 炸弹/资源耗尽）。自动化工具必须控制并发和速率。
- **未授权社工/钓鱼**:除非授权文件明确包含社会工程学测试,否则禁止。
- **未复现猜测**:不得在报告中写入"理论上可能存在"的 finding。必须有 HTTP 包 / 截图 / 命令输出证据。
- **泄露测试信息**:测试过程中获取的所有信息（漏洞/凭据/数据）仅限报告交付,禁止向第三方透露。
- **超范围数据获取**:证明数据可读即可,不批量拖库。已不慎获取的敏感数据立即销毁并在报告中记录。

## 🔀 持久化与痕迹（按作业模式分支）

**默认档 —— 授权渗透测试 / RoE 未授予持久化条款**：❌ **禁止**植入 rootkit、计划任务、自启动项、WMI 订阅、SSP、Skeleton Key 等任何持久化机制。测试结束后所有临时 shell 必须关闭并清理。

**红队评估档 —— 且 RoE 明文授予持久化条款**：允许按 `references/playbooks/intranet-postexp/17-persistence.md` 执行，但必须同时满足三条：

1. **登记制**：每一处持久化登记四要素——主机、机制、植入时间点、约定清理时间点；不得遗漏、不得事后补记。
2. **清理责任明确**：RoE 必须写明由测试方清理，还是移交甲方清理。约定移交的，交付时附**清理清单**（含逐条清除命令）。
3. **超出条款即停**：RoE 未点名的机制（如给了计划任务许可但没给 SSP）不得使用。不确定是否在条款内 → 按默认档处理。

> 判定顺序：先看作业模式，再看 RoE 是否**明文**授予。没有明文授予 = 禁止。不存在"授权了红队所以默认可以持久化"。

## ⚠️ 需确认后执行

以下操作在授权范围内允许,但执行前**必须暂停并与甲方确认**:

- **横向移动到新网段**:拿到内网入口后,每扩展到一个新网段/新系统前先确认是否在授权范围内。
- **接触核心资产**:域控、核心数据库、生产集群等关键系统,触达前先暂停上报。
- **自动化大规模扫描**:使用 sqlmap/nuclei/dirsearch 等工具前,确认目标可承受的流量上限。
- **权限提升到最高**:拿到 root/SYSTEM/Domain Admin 权限后,先暂停记录,确认后再继续后渗透。
- **读取敏感配置**:数据库连接串、云 AK/SK、内部证书等,仅截图证明可达即可,不实际提取使用。

### 授权未覆盖后渗透时的保守底线

若授权书 / RoE **只覆盖漏洞发现与验证**、未包含后渗透条款，拿到下列资产时停在下表的"只读证明"，不得继续深入：

| 你拿到了 | 允许做的"价值证明" | 不允许做的事 |
|---|---|---|
| Webshell / RCE | `whoami` / `hostname` / `ip route` / `/etc/issue` 截图 | 反弹 shell / 写持久化 / 提权 |
| 一组 SSH key | 截图 key 文件 mode + comment（脱敏） | 用 key 登录他人机器 |
| 一组数据库凭据 | 截图凭据存在 + 标记访问权限范围 | 实际连库 / dump 数据 |
| 进入内网（SSRF 触达） | 探测 1-2 个明确受影响端口的 banner | 端口扫描全网段 / 横向移动 |
| AWS / GCP credentials | `aws sts get-caller-identity`（只读 identity） | `aws s3 ls` 等枚举操作 |

若授权 / RoE **明确包含后渗透**，则按上文「⚠️ 需确认后执行」与 Phase 4 执行，本表不适用。

## ✅ 必做

- 越权 / IDOR 用**自己控制的两个账号**自演,不要拿真实用户 ID 试探。
- SSRF / XXE / RCE 外带用**自己的 OOB 域名**（interactsh / 自建 DNSLog）,不要用公共 / 他人 DNSLog。
- 所有操作保留完整日志（时间戳 + 操作 + 结果）,作为证据链。
- 提交报告前用 `references/templates/report-pentest.md` 核对报告结构完整性。
- 提交前对照 CVSS 4.0 vector 给评级,不要凭感觉写 High/Critical。
- 测试结束后执行 Phase 5 的**清理确认**流程,逐项核实无残留。
- 保留所有原始证据（HTTP 包/截图/命令输出）至项目关闭。

## 中止触发条件

下列任一情况立即**中止测试**并上报项目负责人:

- 发现资产超出授权范围且操作已发出
- 操作导致了业务系统异常（响应变慢/服务中断/数据异常）
- 发现了涉及国家安全/公民个人信息大规模泄露等重大问题
- 甲方要求暂停或终止测试
- 测试环境与生产环境未做隔离,存在误伤风险

**中止后流程**:
1. 立即停止所有测试操作
2. 记录当前状态（已执行的操作 + 发现的问题）
3. 通知甲方项目负责人
4. 等待甲方确认后决定是否继续

## 与 Phase 4 的边界

Phase 4（漏洞利用与后渗透）允许在授权范围内进行深度利用、提权和横向移动——这是渗透测试区别于 SRC 的关键。但以下边界不可逾越:

- **深度 ≠ 破坏**:可以提权到 root,但不能删除系统文件
- **横向 ≠ 无限**:每进入一个新系统/网段,先核对是否在授权范围内
- **证明 ≠ 利用**:证明可以读取数据库即可,不需要把整个库拖出来
- 提权 / 横向 / 持久化的**具体许可边界**见上文「🔀 持久化与痕迹（按作业模式分支）」与「⚠️ 需确认后执行」两节,本节只给原则
